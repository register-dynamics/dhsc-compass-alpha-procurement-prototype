{# Search2: a second version of search, reached from "Search2" in the header. Modelled on RS Components. Search results only ever list devices, and categories, device types and suppliers are ways in. As someone types, suggestions offer each kind of page, so someone after a branded device goes straight to it rather than scrolling past categories and device types. ── How it works ────────────────────────────────────────────────────────── Without JavaScript this is a plain search form: Enter goes to the results page. The suggestions are accessible-autocomplete (GOV.UK's tested combobox) added on top, so the search still works if the script fails. - The first suggestion is always "Search for [what you typed]", and it is highlighted, so Enter searches the typed text, as it would without the dropdown. Picking any other suggestion goes straight to its page. - Each suggestion starts with its type ("Device type", "Category"). Group headings inside the list are announced unreliably by screen readers, so the type goes in every option instead. - At most 3 of each type, in this order: devices, device types, categories, suppliers. Devices first, since they are what the search is for. - Suggestions appear from 2 characters. Words can come in any order, and each matching word is bold. - confirmOnBlur is off, so tabbing away never takes someone to a page they did not choose. - accessible-autocomplete 3.0.2, the latest, rather than the 2.0.4 the rest of the prototype uses. Its input gets the nhsuk-input class, and components/_search-suggestions.scss swaps its GOV.UK styles for NHS ones. ── Not covered by NHS guidance ─────────────────────────────────────────── The NHS Design System has no search suggestions component, pattern or guidance. The search input component covers only the box. This follows the NHS website's header search, which does suggest as you type, and GOV.UK's accessible-autocomplete, which sits outside the GOV.UK Design System too. Components/select.md says some users, "especially people who use a keyboard to navigate and people with motor difficulties", struggle with dropdowns. So the dropdown is only ever a shortcut: the search works without it. Needs testing with assistive technology before anyone relies on it: VoiceOver, NVDA and JAWS (announcements, and choosing a suggestion changes page rather than filling the box), screen magnifiers (the list may fall outside the magnified area) and speech control. Share findings on the NHS service manual community backlog. ── Content ─────────────────────────────────────────────────────────────── The suggestions are the dummy data from Search results and the other sketch pages. Pages that do not exist yet link to "#". Search results is the existing mockup, fixed on "spinal fixation", so it ignores the term.
